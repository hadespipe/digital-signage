# Slideshow crossfade — Issue #2

วันที่: 2026-11-07

Issue: https://github.com/hadespipe/digital-signage/issues/2

สถานะ: ผู้ใช้อนุมัติแล้ว — กำลังจัดทำแผน implementation

## เป้าหมายและขอบเขตที่ยืนยัน

- เปลี่ยนจากการตัดภาพทันทีเป็น crossfade ระหว่างภาพ ระยะเวลา 300 ms ทั้งบนแอปทีวีและหน้าพรีวิวสไลด์โชว์
- ภาพใหม่ค่อย ๆ ปรากฏซ้อนภาพเดิม โดยไม่มีช่วง fade ผ่านจอดำ และรูปสุดท้ายวนกลับรูปแรกด้วยพฤติกรรมเดียวกัน
- รอบสไลด์ยังเป็น 2,000 ms รวมเวลา transition ไม่เพิ่มเป็น 2,300 ms
- ทำงานบน branch ใหม่ `codex/slideshow-crossfade` แยกจาก `main`
- ไม่ทำ Issue #3: ยังใช้ `contain` รักษาสัดส่วน แสดงภาพครบ พื้นหลังดำ ไม่เปลี่ยนเป็นเต็มจอแบบครอป

สเปคนี้แทนที่ข้อกำหนดเดิมเรื่อง “ไม่ใส่เอฟเฟกต์เปลี่ยนภาพ” เฉพาะสไลด์โชว์ ส่วนข้อกำหนดด้านความปลอดภัย การตั้งค่า และการจัดเก็บยังใช้ตามสเปคหลัก

## จังหวะการแสดงผล

- ภาพแรกปรากฏทันทีเมื่อพร้อม ไม่ fade จากจอดำ
- ให้ T เป็นเวลาที่ภาพแรกแสดง: ภาพแรกค้างถึง T+1,700 ms จากนั้น crossfade 300 ms ให้ภาพที่สองแสดงเต็มที่ที่ T+2,000 ms
- ภาพที่สองค้างถึง T+3,700 ms แล้ว crossfade ให้ภาพที่สามแสดงเต็มที่ที่ T+4,000 ms และวนตามจังหวะเดิม
- เวลา animation ไม่สะสมเพิ่มในรอบสไลด์ ไม่เริ่มจับรอบ 2,000 ms ใหม่หลัง transition จบ เบราว์เซอร์อาจหน่วงได้ตามข้อจำกัดของอุปกรณ์ จึงต้องวัดบนทีวีจริง
- ระหว่าง crossfade เก็บภาพเดิมไว้ทึบเต็มที่ใต้ภาพใหม่ แล้วเพิ่ม opacity ภาพใหม่จาก 0 เป็น 1 แบบ linear เพื่อไม่ให้พื้นดำแทรกระหว่างภาพ ใช้สองชั้นภาพที่จัดตำแหน่งตรงกันและเลี่ยง animation ที่เปลี่ยน layout
- เมื่อจบ transition ให้เหลือภาพใหม่เป็นภาพหลัก และนำภาพเก่าออกจากชั้นที่มองเห็น

## สถานะและการขัดจังหวะ

- มีรูปเดียว: แสดงค้าง ไม่มี transition ซ้ำเข้าหาตัวเอง
- ไม่มีรูปที่เซิร์ฟเวอร์ยืนยัน: ยกเลิก transition และแสดง `Please upload` ทันที ไม่มีภาพเก่าหรือ callback เก่ากลับมาทับข้อความ
- โหลดรายการใหม่: ระหว่างโหลดให้ชุดเดิมเล่นต่อ เมื่อรูปชุดใหม่พร้อมครบ ให้ยกเลิก transition เดิม สลับเป็นภาพแรกของชุดใหม่ทันที แล้วเริ่มรอบ 2,000 ms ใหม่ ไม่เพิ่ม crossfade ระหว่างชุดในงานนี้
- ถ้าโหลดรายการหรือรูปชุดใหม่ไม่สำเร็จ ให้เล่นชุดล่าสุดที่สำเร็จต่อไปตามพฤติกรรมเดิม ไม่ตีความเป็นรายการว่าง
- หยุด player เปลี่ยนการตั้งค่าเซิร์ฟเวอร์ หรือออกจาก preview: ยกเลิก timer/animation ที่เกี่ยวข้อง และไม่ให้ callback ของรอบเก่ากลับมาแก้ UI
- ภาพและ blob URL ที่ยังแสดงอยู่ระหว่าง transition ต้องไม่ถูก release ก่อนเลิกใช้งาน เคลียร์ทั้งสองชั้นก่อนคืนทรัพยากรที่ไม่ใช้แล้ว
- หน้าตั้งค่าทีวี รีโมต Back และข้อความเชื่อมต่อผิดพลาดยังทำงานตามเดิม
- หากผู้ใช้เปิด `prefers-reduced-motion: reduce` ให้ตัดภาพทันทีตามรอบ 2,000 ms แทน crossfade โดยไม่มีเวลารอ transition

## แนวทาง implementation และพื้นที่ที่ต้องตรวจ

ข้อเสนอของผู้พัฒนา: ใช้ CSS opacity transition และภาพสองชั้น ไม่เพิ่ม dependency หรือ animation framework การแบ่ง helper/API ภายในให้ผู้ implement ตัดสินใจตามโค้ดเดิม โดยรักษา player ร่วมระหว่างทีวีกับ preview และหลีกเลี่ยง timing สองชุดที่ไม่ตรงกัน

- `tv/player.js` และ `tv/player.d.ts`: จังหวะเริ่ม/จบ transition, lifecycle และสัญญากับ view
- `tv/main.js`, `tv/index.html`, `tv/style.css`: ภาพสองชั้น การล้างสถานะ และการเชื่อมกับหน้าตั้งค่าทีวี
- `admin/src/Preview.tsx`, `admin/src/style.css`: พฤติกรรมเดียวกันใน preview โดยไม่เปลี่ยน thumbnail/editor
- `tv/transport.js`: ตรวจ ownership และอายุ blob URL กับการ preload เดิม ปรับเฉพาะหากจำเป็น
- tests ของ player, preview และ TV รวมถึงเอกสาร verification/คู่มือที่อธิบายพฤติกรรมการแสดงผล

คง syntax/API ที่รองรับ Chromium 79 และเส้นทาง authentication เดิม การสลับภาพต้องใช้รูปที่โหลดพร้อมแล้ว ไม่มี request ใหม่ทุกครั้งที่เริ่ม fade

## เกณฑ์ตรวจรับและหลักฐาน

- ทดสอบด้วย clock ที่ควบคุมได้: เริ่ม fade ที่ 1,700 ms จบที่ 2,000 ms และรอบถัดไปจบที่ 4,000 ms ไม่มีการบวกระยะ fade เพิ่มในรอบ
- ทดสอบ browser ระหว่าง 300 ms ว่าภาพเดิมยังอยู่ใต้ภาพใหม่ และ opacity ภาพใหม่มีค่าระหว่าง 0 กับ 1 ไม่ตรวจแค่การเปลี่ยน `src`
- ตรวจการวนภาพสุดท้ายกลับภาพแรก รวมทั้ง 0/1/5 รูป, reduced motion และการเปลี่ยนรายการเป็นชุดใหม่/ว่างระหว่าง fade
- ตรวจ stop/unmount และเปลี่ยน settings ระหว่าง fade ว่าไม่มี stale callback หรือการใช้ blob URL หลัง release
- ตรวจเครือข่ายขัดข้อง/กลับมาเชื่อมต่อ การอัปเดตรายการ และหน้าตั้งค่าทีวีโดยไม่ทำให้พฤติกรรมเดิมถดถอย
- รัน typecheck, tests ที่เกี่ยวข้อง, admin build, TV syntax check และ package ใหม่ตาม scripts ของโปรเจกต์
- บันทึกผลทดสอบบน LG OLED48C1PTB / Chromium 79 แยกจาก browser tests: ความต่อเนื่องของ fade รอบ 2 วินาที และการวนกลับ ไม่มีเฟรมว่างหรือการกระพริบจากการสลับชั้นภาพ
- หากยังเข้าถึงทีวีไม่ได้ ให้ระบุ hardware verification ว่ายังไม่ทดสอบ ห้ามใช้การ build/package ผ่านแทนผลทดสอบจริง

## สิ่งที่ไม่ทำและความเสี่ยง

- ไม่เพิ่มตัวเลือก transition, ระยะ fade ที่ตั้งค่าได้, zoom/slide หรือปรับความยาวรอบสไลด์
- ไม่แก้ Issue #3 ไม่แก้ไฟล์ภาพต้นฉบับ และไม่รับรองว่าจะลบแถบดำจากสัดส่วนภาพได้
- ภาพสองชั้นอาจเพิ่มภาระ compositing/หน่วยความจำของทีวี ความลื่นไหลจริงต้องตรวจบนฮาร์ดแวร์ ไม่รับรองจาก browser desktop เพียงอย่างเดียว
