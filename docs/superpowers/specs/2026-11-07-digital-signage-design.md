# Digital Signage สำหรับ LG webOS

วันที่: 2026-11-07

สถานะ: ผู้ใช้อนุมัติข้อกำหนดทั้งหมด รวมข้อเสนอของผู้พัฒนา เมื่อ 2026-11-07

## ความต้องการที่ผู้ใช้ยืนยัน

- ทีวี LG OLED48C1PTB (ข้อมูลผู้ผลิตระบุ webOS 6.0)
- ติดตั้งแอปผ่าน Developer Mode
- แอดมินอัปโหลดรูปผ่านเว็บไซต์ มีรูปที่ใช้งานได้สูงสุด 5 รูป
- ทีวีแสดงสไลด์โชว์ เปลี่ยนรูปทุก 2 วินาที และวนซ้ำ
- เมื่อไม่มีรูป ให้แสดงข้อความตรงตัวว่า `Please upload`

## ทางเลือกและวิธีที่เลือก

1. แอป webOS `.ipk` ติดตั้งผ่าน Developer Mode: เหมาะกับการติดตั้งใช้เองและทดสอบกับเครื่องจริง แต่ต้องต่ออายุ Developer Mode ผู้ใช้เลือกวิธีนี้
2. แอปเผยแพร่ผ่าน LG Content Store: ติดตั้งผ่านสโตร์ได้ แต่ต้องส่งตรวจและผ่านการอนุมัติ จึงยังไม่ทำในระยะแรก

ไม่ใช้ APK เพราะเป้าหมายเป็น LG webOS

## เทคโนโลยีที่ผู้ใช้ยืนยัน

- เว็บแอดมินใช้ React + TypeScript + Vite เป็นแอปฝั่งเบราว์เซอร์ รวมหน้าพรีวิวสไลด์โชว์ โดย build เป็นไฟล์ static ให้เซิร์ฟเวอร์เสิร์ฟ ไม่ใช้ Next.js หรือ server-side rendering ในระยะแรก
- เซิร์ฟเวอร์ใช้ TypeScript รันด้วย Bun และใช้ Hono จัดการ API และ middleware รวมถึงให้บริการไฟล์เว็บแอดมินและไฟล์รูป
- แอปทีวีใช้ HTML/CSS/JavaScript ธรรมดาแยกจากเว็บแอดมิน โดยเลือก syntax และ Web API ที่รองรับ webOS 6.0 (Chromium 79) ไม่ต้องติดตั้ง Bun บนทีวี
- เลือก Bun เพื่อใช้ runtime และเครื่องมือพัฒนาในชุดเดียว ไม่กำหนดว่า Bun ต้องเร็วกว่า Node.js และไม่รับรองตัวเลขความเร็วโดยไม่มีผลวัดจากแอปจริง การวนสไลด์ทุก 2 วินาทีทำบนทีวีหลังโหลดรูป ไม่ขึ้นกับความเร็ว runtime ฝั่งเซิร์ฟเวอร์โดยตรง

## ขอบเขตและข้อเสนอของผู้พัฒนา

รายการต่อไปนี้เป็นค่าเริ่มต้นที่ผู้พัฒนาเสนอ และอยู่ในการอนุมัติข้อกำหนดทั้งหมดเมื่อ 2026-11-07:

- แอดมินหนึ่งบัญชี ทีวีหนึ่งเครื่อง และรายการรูปส่วนกลางหนึ่งรายการ
- เซิร์ฟเวอร์กลางให้บริการเว็บแอดมิน API และไฟล์รูป ทีวีและเว็บเข้าถึงผ่านอินเทอร์เน็ตได้ ไม่ต้องอยู่ Wi-Fi เดียวกันหลังติดตั้ง
- จัดเตรียม Docker และคู่มือโฮสต์ที่รองรับเซิร์ฟเวอร์ทำงานต่อเนื่องและพื้นที่เก็บไฟล์ถาวร แต่ยังไม่ซื้อบริการหรือเผยแพร่จริงจนทราบโฮสต์และโดเมนของผู้ใช้
- รองรับการรันบนคอมพิวเตอร์ในเครือข่ายเดียวกับทีวีสำหรับทดสอบก่อนขึ้นโฮสต์จริง

## เว็บแอดมิน

- หน้าเข้าสู่ระบบด้วยรหัสผ่านแอดมินที่ตั้งผ่านตัวแปรสภาพแวดล้อม ไม่มีรหัสผ่านค่าเริ่มต้นในซอร์สโค้ด
- ใช้ session ฝั่งเซิร์ฟเวอร์ พร้อม cookie HttpOnly, SameSite และ Secure เมื่อใช้งาน HTTPS ป้องกันการแก้ไขข้อมูลข้ามเว็บไซต์และจำกัดการลองรหัสผ่าน
- แสดงรูปตัวอย่าง จำนวนรูปจาก 5 รูป และลำดับการแสดง
- อัปโหลดได้หลายไฟล์ภายในจำนวนที่เหลือ รองรับ JPEG, PNG และ WebP แบบภาพนิ่ง จำกัด 10 MB ต่อไฟล์ พร้อมตรวจชนิดและถอดรหัสภาพจริงฝั่งเซิร์ฟเวอร์
- แปลงรูปเป็น JPEG สำหรับแสดงบนทีวี แก้ทิศภาพตาม EXIF และย่อให้อยู่ภายใน 3840×2160 โดยคงสัดส่วน
- ลบรูปและเปลี่ยนลำดับได้ รูปใหม่เพิ่มท้ายรายการ
- บังคับเพดาน 5 รูปฝั่งเซิร์ฟเวอร์ด้วย แม้มีคำขออัปโหลดพร้อมกัน
- มีหน้าพรีวิวสไลด์โชว์บนเบราว์เซอร์เพื่อทดสอบก่อนใช้ทีวีจริง

## แอปทีวี

- ส่งมอบซอร์สแอปและแพ็กเกจ `.ipk` พร้อมไอคอน ชื่อแอป และข้อมูลแพ็กเกจ webOS
- ครั้งแรกให้ตั้ง URL เซิร์ฟเวอร์และโทเคนอ่านรูปผ่านหน้าตั้งค่าที่ใช้รีโมตได้ บันทึกไว้ในเครื่องและไม่ฝังความลับแอดมินในแพ็กเกจ
- เปิดแอปแล้วแสดงรูปโดยไม่มีเมนูทับภาพ เปิดหน้าตั้งค่าซ้ำได้จากปุ่มที่คู่มือระบุ และรองรับปุ่ม Back ตามพฤติกรรม webOS
- พื้นหลังดำ แสดงรูปทั้งภาพโดยรักษาสัดส่วน ไม่ตัดขอบ ไม่ใส่เอฟเฟกต์เปลี่ยนภาพ
- เริ่มแสดงภาพแรกหลังโหลดสำเร็จ จากนั้นวนทุก 2 วินาที ถ้ามีหนึ่งรูปให้ค้างภาพนั้น
- ตรวจสอบเวอร์ชันรายการรูปจากเซิร์ฟเวอร์ทุก 5 วินาที เมื่อมีการเปลี่ยนแปลงให้โหลดรูปชุดใหม่ให้พร้อมแล้วสลับชุด เพื่อไม่ให้จอดำระหว่างดาวน์โหลด เวลาที่รูปใหม่ปรากฏขึ้นอยู่กับความเร็วเครือข่ายด้วย
- ถ้าเซิร์ฟเวอร์ยืนยันว่ารายการว่าง ให้ล้างชุดรูปเดิมและแสดง `Please upload` กลางจอ
- เครือข่ายขัดข้องไม่ถือว่ารายการว่าง ให้แสดงรูปชุดล่าสุดที่โหลดสำเร็จต่อไปในรอบการเปิดแอปนั้น และลองเชื่อมต่อใหม่อัตโนมัติ
- ถ้ายังไม่มีรูปที่โหลดสำเร็จและเชื่อมต่อไม่ได้ ให้แสดงสถานะเชื่อมต่อขัดข้องแยกจาก `Please upload`
- ระยะแรกไม่รับประกันการเก็บรูปข้ามการปิดแอปแบบออฟไลน์ ไม่ทำเปิดแอปเองเมื่อเปิดทีวี และไม่ดัดแปลงระบบหรือปิดกลไกป้องกันจอของทีวี

## ข้อมูลและการเชื่อมต่อ

- เก็บเมทาดาทาเวอร์ชันรายการ ลำดับรูป และชื่อไฟล์ในพื้นที่ถาวรบนเซิร์ฟเวอร์ เขียนข้อมูลแบบ atomic และจัดคำขอแก้ไขตามลำดับ
- ใช้ชื่อไฟล์ที่ระบบสร้างใหม่และไม่ซ้ำ ตรวจสิทธิ์ทุก API แก้ไขข้อมูล
- API อ่านรายการและไฟล์รูปใช้โทเคนอ่านอย่างเดียวแยกจากสิทธิ์แอดมิน ส่งใน header และไม่ใส่ใน URL หรือ log
- ใช้ HTTPS บนโฮสต์จริง โทเคนอ่านหมุนเปลี่ยนได้ผ่านการตั้งค่าเซิร์ฟเวอร์ โดยต้องตั้งค่าใหม่ที่ทีวีหลังเปลี่ยน
- เมื่อรายการเปลี่ยนระหว่างดาวน์โหลด ให้ยึดเวอร์ชันรายการที่ครบถ้วนล่าสุด และลองโหลดใหม่หากไฟล์ถูกลบระหว่างทาง

## สิ่งที่ไม่รวม

- วิดีโอ เพลง ตารางเวลา หลายเพลย์ลิสต์ หลายบัญชี และการควบคุมทีวีจากระยะไกล
- การเผยแพร่ผ่านสโตร์ การต่ออายุ Developer Mode อัตโนมัติ หรือรับประกันว่าแอปจะยังติดตั้งอยู่เมื่อ Developer Mode หมดอายุ

## การส่งมอบและตรวจสอบ

- ซอร์สเว็บ เซิร์ฟเวอร์ และแอปทีวี คู่มือรันในเครื่อง/โฮสต์ ตั้งค่ารหัสผ่านและโทเคน และขั้นตอนติดตั้งผ่าน LG Developer Mode
- ตรวจสอบการเข้าสู่ระบบ สิทธิ์อ่าน/เขียน การตรวจไฟล์ เพดาน 5 รูปรวมกรณีอัปโหลดพร้อมกัน ลบ/เรียงลำดับ และข้อมูลยังอยู่หลังเซิร์ฟเวอร์เริ่มใหม่
- ตรวจการ build เว็บ React ด้วย Vite และการเสิร์ฟไฟล์ที่ build แล้วผ่านเซิร์ฟเวอร์ Bun + Hono
- ยืนยันความเข้ากันได้ของ dependency กับ Bun บน Docker/ระบบปฏิบัติการเป้าหมาย โดยเฉพาะการอัปโหลดและแปลงภาพ การจัดการ session และการเขียนข้อมูลถาวร ก่อนรับรองพร้อมใช้งานจริง
- ตรวจสไลด์ 0/1/5 รูป การเปลี่ยนทุก 2 วินาที การรับรายการใหม่ และการแสดงรูปต่อเมื่อเน็ตหลุด
- ทดสอบพรีวิวบนเบราว์เซอร์ ตรวจแพ็กเกจ webOS และแยกผลทดสอบบนทีวีจริงออกจากการทดสอบบนคอมพิวเตอร์อย่างชัดเจน
- การติดตั้งและยืนยันบนทีวีจริงต้องมีการเชื่อมต่อถึงทีวี และผู้ใช้เปิด Developer Mode/Key Server ไม่ถือว่าทดสอบบนเครื่องจริงแล้วจากการสร้างไฟล์ `.ipk` สำเร็จเพียงอย่างเดียว
